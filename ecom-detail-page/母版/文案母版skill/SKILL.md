# 全品类详情页文案母版

## 母版定位

这是一个“详情页文案 workflow 母版”，不是某个具体品类的最终版本。

它负责定义：
1. 通用主流程
2. 信息完整度判断
3. 检查点机制
4. 文案大纲与成稿结构
5. 品类扩展接口

它不直接负责：
1. 某个品类的专业参数库
2. 某个品类的固定风格话术
3. 某个品类的专属竞品字段

## 适用范围

### 可扩展品类
- 3C数码
- 美妆个护
- 家居日用
- 食品饮料
- 母婴用品
- 服饰鞋包
- 宠物用品
- 运动户外
- 小家电

### 不适用场景
- 需要医疗、法律、金融等高风险合规审校的专业宣传文案
- 纯品牌故事页、招商页、招商手册
- 用户明确要短视频脚本、社媒种草贴、直播口播，而不是详情页

## 三层架构

任何品类实现都必须按三层拆分：

### 第一层：通用主流程
固定不变，所有品类共用：
1. 识别需求
2. 判断信息完整度
3. 采集或补齐关键信息
4. 信息确认检查点
5. 竞品筛选与比较维度确认
6. 文案大纲预览检查点
7. 生成完整详情页文案
8. 输出前自检

### 第二层：品类分支
由具体品类 skill 补充：
1. 该品类要问哪些关键参数
2. 该品类的竞品对比维度是什么
3. 该品类有哪些高频卖点结构
4. 该品类适合哪些配图方向

### 第三层：风格分支
由具体项目或品牌风格补充：
1. 是科技感、质感、成分感、治愈感，还是强促销感
2. 标题节奏要极简还是偏强转化
3. 价值表达偏理性还是偏场景化

## 通用工作流

```text
识别需求
→ 判断信息是否足够
→ 选择首轮响应模板
→ 采集或补齐信息
→ 信息确认检查点
→ 确定竞品与对比维度
→ 文案大纲预览
→ 文案预览确认检查点
→ 生成完整详情页
→ 自检后输出 Markdown
```

## 信息完整度规则

### 最小信息集
进入完整详情页生成前，至少尽量拿到以下信息：
1. 产品名
2. 品类
3. 价格或价格带
4. 2 到 3 个核心卖点
5. 目标用户或使用场景
6. 竞品或参考价位段

### 快路径规则
如果用户已经给出以下大部分信息，可直接进入“信息确认 + 大纲预览”：
1. 产品名
2. 品类
3. 价格信息
4. 至少 2 个明确卖点
5. 竞品或竞品价位段
6. 目标人群或核心场景

不要命中快路径的情况：
- 连品类都不清楚
- 卖点全是空泛形容词
- 关键事实严重不足，继续出稿会大量编造

## 首轮响应模板

### 模板A：信息不足

```markdown
可以，我先帮你把详情页的方向搭起来。

为了避免直接编内容，我先补 5 个关键信息：
1. 产品名称和品类？
2. 售价或预计售价？
3. 最想突出的 3 个卖点是什么？
4. 主要竞品是谁，或者同价位有哪些对手？
5. 目标用户是谁，主要使用场景是什么？

你按顺序回复就行，我收到后会先做信息确认，再给你文案大纲。
```

### 模板B：信息中等

```markdown
我先把你已经给的信息收一下，避免重复追问。

### 当前已知信息
- **产品名称**：[产品名]
- **品类**：[品类]
- **价格信息**：[价格]
- **已知卖点**：[卖点]
- **已知竞品**：[竞品/价格带]
- **已知场景**：[场景]

为了让详情页更准，我还需要补这几项：
1. [缺失项1]
2. [缺失项2]
3. [缺失项3]

你补完后，我直接给你大纲预览。
```

### 模板C：信息较全

```markdown
你给的信息已经够我先搭一版详情页方向了，我先做信息确认，再给你文案大纲预览。

### 产品信息汇总
- **产品名称**：[产品名]
- **产品类别**：[类别]
- **价格信息**：[售价/版本]
- **核心卖点**：[卖点1 / 卖点2 / 卖点3]
- **竞品范围**：[竞品]
- **目标人群**：[人群/场景]
- **待补充细节**：[缺失但不阻碍起稿的信息]

### 详情页文案大纲预览
- **主标题方向**：[标题方向]
- **副标题方向**：[副标题方向]
- **卖点顺序**：[卖点排序]
- **竞品对比重点**：[重点]

如果方向没问题，我下一条就展开成完整详情页文案。
```

## 通用信息池

具体品类实现可以删减、替换，但不要丢掉通用骨架。

### 基础信息
1. 产品名称/型号
2. 品类
3. 品牌定位
4. 价格或价格带
5. 上市状态

### 卖点信息
6. 最想打的 2 到 3 个核心卖点
7. 相比竞品的主要差异
8. 相比上代/旧款的升级点

### 竞品信息
9. 主要竞品
10. 竞品价格带
11. 用户为什么会拿这些竞品来比较

### 用户信息
12. 目标人群
13. 使用场景
14. 用户痛点
15. 购买动机

### 补充事实
16. 核心参数/成分/材质/规格
17. 权威认证/测试/背书
18. 售后、包装、赠品、服务权益

## 通用硬性规则

1. 只输出 Markdown
2. 不编造参数、成分、价格、认证、销量、榜单
3. 没核实的数据，不写成精确结论
4. 每个卖点都必须同时包含“事实支撑 + 用户价值 + 配图建议”
5. 标题不能空泛，副标题要有明确价值主张
6. 文案要先准确，再好看，再有风格

## 广告法与极限词约束

所有品类统一遵守以下规则：
1. 不使用“国家级、最高级、最佳、第一、唯一、顶级、极致、完美、万能、永久、100%”等极限词
2. 不使用“全网第一、销量第一、行业第一、冠军同款、史上最强、零风险、零刺激、绝对安全”这类无法充分举证的广告法高风险表述
3. 不把普通卖点写成保证性承诺，如“根治、彻底解决、百分百见效、永不复发”
4. 如用户原话包含极限词，输出时也要主动降级改写成可落地、可核实的表达

优先改写方式：
- “更适合”
- “更偏向”
- “更适用于某类场景”
- “在同价位中有竞争力”
- “基于已知信息，优势集中在”

## 品类扩展接口

每个具体品类都要补充以下 4 块：

### 接口1：品类关键问题池
例：
- 3C 看参数、续航、性能、生态
- 美妆看成分、功效、肤感、适用肤质
- 家居看材质、尺寸、工艺、空间适配

### 接口2：竞品对比维度
例：
- 3C 比性能、参数、价格、生态
- 食品比口味、配料、规格、热量、场景
- 母婴比安全、材质、年龄段、使用便捷性

### 接口3：卖点结构模板
例：
- 科技品偏“参数 → 场景 → 对比”
- 美妆偏“成分 → 功效 → 肤感”
- 家居偏“材质 → 设计 → 空间场景”

### 接口4：风格模板
例：
- 3C 可偏科技感、极简感
- 食品可偏食欲感、场景感
- 母婴可偏安心感、照护感

## 输出前自检

- [ ] 信息来源是否可靠
- [ ] 是否错误套用了其他品类模板
- [ ] 是否存在编造成分/参数/认证
- [ ] 卖点是否和目标人群匹配
- [ ] 对比维度是否真的可比
- [ ] 配图建议是否能落地

## 建议落地方式

推荐用法：
1. 先保留这份母版不动，作为标本
2. 每新增一个品类，就复制一份并补“品类分支”
3. 让每个子 skill 只负责一个品类或一组强相关品类
