## 继承自母版的基础能力

这个品类默认继承了母版的通用能力：

1. 信息完整度判断
2. 快路径与补问路径切换
3. 信息确认检查点
4. 竞品与对比方向确认
5. 文案大纲预览
6. 成稿结构骨架
7. 输出前自检

这些通用能力的作用是保证不同品类都按同一条主流程运行，不会每个品类各写各的 workflow。

## 本品类专属优化

这次精修重点补的是食品饮料特有的执行细节。

### 1. 强化了合规边界

重点约束了以下高风险表达：
- 减肥、瘦身、控糖、降脂、治疗、养胃、助眠等保健或治疗表述
- “零负担”“绝对健康”“无糖无卡”这类绝对化营养承诺
- 某个热量、糖分、蛋白质数值
- 功能饮品对体能、情绪、睡眠的结果承诺
- 极限词和广告法高风险术语

同时补了降级写法，避免在信息不足时硬写健康功效。

### 2. 补了食品饮料专用快路径

当用户已经给出：
- 产品名和品类
- 规格与价格
- 至少 2 个卖点
- 原料/配料/口味中的至少 1 类信息
- 竞品或价格带
- 食用场景或目标人群

就允许直接进入“信息确认 + 大纲预览”，减少不必要追问。

### 3. 补了更贴合食品饮料的首轮提问逻辑

和通用母版相比，这里首轮更关注：
- 原料和配料亮点
- 营养标签是否有依据
- 口味、口感、风味层次
- 包装规格与便利性
- 竞品、价格带与食用场景

### 4. 补了分品类问题池

当前已经按以下子类拆开了提问重点：
- 零食糕点
- 冲饮饮品/茶咖
- 健康轻食/功能饮品
- 粮油调味/即食食品

这样可以减少“用同一套问题问所有食品饮料”的问题。

### 5. 重写了卖点结构

当前推荐顺序是：

`原料/配料 → 口味体验 → 营养/轻负担 → 包装规格 → 食用场景`

这比通用卖点结构更适合食品饮料，也更容易写出“真实、有食欲、有信任感”的详情页。

### 6. 补了可落地的配图建议

当前优先建议：
- 开袋/冲泡/倒杯场景图
- 原料与配料特写
- 营养信息图
- 包装规格图
- 食用场景图
- 口味/风味对照图
- 食用方式示意图
