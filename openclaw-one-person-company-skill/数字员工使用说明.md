## 一、团队理念

### ClawLab 是什么？

**ClawLab 数字员工团队**是一个由 18 个 AI Agent 组成的智能协作体系。  
每个 Agent 都有独立的角色定位、专属的 Soul（灵魂文件）、清晰的职责边界和可量化的 KPI。

它不是一个聊天机器人，它是一家真正在运转的**数字公司**。

---

### 核心理念

**「一人操盘，十八人出力」**

> 你是这家公司真正的老板。你只需要告诉 CEO 你想要什么，剩下的由 18 位数字员工协作完成。

ClawLab 建立在三个核心信条之上：

```
① 专注胜于全能    每个 Agent 只做自己最擅长的事
② 协作胜于单打    跨部门通信让复杂任务得以分解
③ 数据胜于感觉    每个决策都有 KPI 指标可追踪
```

---

### 设计原则

| 原则 | 说明 |
|------|------|
| **角色专一** | 每个 Agent 有且只有一个核心职责，不越界 |
| **层级清晰** | CEO → 部门负责人 → 执行角色，三层递归最大深度 |
| **双向通信** | 任意 Agent 均可主动联系关联角色，不存在信息孤岛 |
| **结果导向** | 每个 Agent 有明确 KPI，输出必须可量化 |
| **有限自治** | Agent 在职责范围内自主决策，超出范围向上汇报 |

## 三、部门构成

### 🏢 总办（1人）

| 角色 | ID | 职责 | KPI |
|------|----|------|-----|
| CEO | `ceo` | 战略决策、资源分配、最终裁决 | 公司整体增长与盈利 |

**CEO 的核心工作：**
- 制定公司 OKR，分解到三大中心
- 处理跨中心资源冲突
- 审批重大产品/技术/营销决策
- 监控公司整体健康度指标

---

### 🎯 产品增长中心（5人）

> **核心使命：** 打造用户留得住的产品

| 角色 | ID | 职责 | KPI |
|------|----|------|-----|
| 产品负责人 | `product_lead` | 产品方向决策、Roadmap 管理 | 留存率 |
| 用户研究官 | `user_researcher` | 用户洞察、需求挖掘 | 需求准确率 |
| 数据分析师 | `data_analyst` | 数据分析、指标体系建设 | 决策支持效率 |

| 体验优化官 | `ux_optimizer` | 交互设计、体验优化 | 核心功能使用率 |

**部门工作流：**
```
用户研究官 ──→ 数据分析师 ──→ 功能策划官 ──→ 体验优化官
   (洞察)        (验证)         (PRD)          (交互)
```

## 四、通信机制

### 通信层级

ClawLab 采用**三层递归通信模型**，最大递归深度 = 3：

```
第一层：CEO（总指挥）
    ↕ 双向通信
第二层：product_lead / tech_lead / growth_lead（部门负责人）
    ↕ 双向通信
第三层：执行角色（user_researcher / architect / content_planner 等）
```

> ⚠️ 超过 3 层的递归调用会被系统自动终止，防止无限循环。

---

### 跨部门通信矩阵

| 发起方 | 可直接联系 |
|--------|----------|
| CEO | 全部 17 个 Agent |
| product_lead | ceo, user_researcher, data_analyst, feature_planner, ux_optimizer, tech_lead, growth_lead |
| tech_lead | ceo, product_lead, growth_lead, 及技术中心全员 |
| growth_lead | ceo, product_lead, tech_lead, 及增长中心全员 |
| data_analyst | product_lead, user_researcher, growth_lead, crm_analyst, devops_engineer |
| feature_planner | product_lead, user_researcher, data_analyst, ux_optimizer, tech_lead |
| frontend_dev | tech_lead, architect, backend_dev, qa_engineer, ux_optimizer, feature_planner |

---

### agentToAgent 通信规则

```json
{
  "agentToAgent": {
    "enabled": true,
    "allowCrossAgent": true,
    "logCommunication": true
  },
  "maxRecursion": 3
}
```

- ✅ 允许跨部门通信
- ✅ 所有通信记录到日志
- ✅ 支持持久化 Memory（每个 Agent 有独立记忆空间）

## 五、如何运转

### 标准运转流程

ClawLab 的日常运转遵循以下循环：

```
你（老板）
   │
   ▼
① 提出需求 → CEO 接收
   │
   ▼
② CEO 分析 → 识别职能归属 → 委派任务
   │
   ├──→ 产品相关 → product_lead 牵头
   ├──→ 技术相关 → tech_lead 牵头
   └──→ 增长相关 → growth_lead 牵头
          │
          ▼
③ 部门负责人拆解任务 → 分配给执行角色
          │
          ▼
④ 执行角色产出结果 → 汇报给部门负责人
          │
          ▼
⑤ 部门负责人汇总 → 向 CEO 汇报
          │
          ▼
⑥ CEO 审核结果 → 输出最终交付物给你
```

---

### 任务触发方式

| 触发方式 | 说明 | 示例 |
|---------|------|------|
| **直接问 CEO** | 最通用方式，CEO 自动调度 | "帮我制定一个新功能的上线方案" |
| **直接问负责人** | 已知职能归属时 | "product_lead，帮我分析一下留存下降的原因" |
| **直接问执行角色** | 需要特定专业输出时 | "data_analyst，给我出一份本月 DAU 分析报告" |
| **广播（CEO 专属）** | 需要全员参与时 | CEO 向所有 Agent 发送全局指令 |

---

### 决策权限说明

| 决策类型 | 审批层级 |
|---------|---------|
| 公司战略调整 | CEO 独立决策 |
| 产品 Roadmap 变更 | product_lead 提案 → CEO 审批 |
| 技术架构重构 | tech_lead 提案 → CEO 知悉 |
| 增长预算 > 20% 调整 | growth_lead 提案 → CEO 审批 |
| 对外重大营销内容 | content_planner 起草 → growth_lead 审核 → CEO 审批 |
| 功能上线 | qa_engineer 质量报告 → tech_lead 审批 |
| 灰度部署 | devops_engineer 执行 → tech_lead 审批 |

---

### Memory 机制

每个 Agent 拥有独立的记忆空间，跨会话保持上下文：

| Agent 范围 | Memory Scope |
|-----------|-------------|
| CEO | `global`（全局，可读取所有上下文） |
| product_lead + 产品团队 | `product` |
| tech_lead + 技术团队 | `tech` |
| growth_lead + 增长团队 | `growth` |

| data_analyst | `data` |

## 七、使用指南

### 如何开始对话

与 ClawLab 团队对话时，推荐使用以下方式：

**① 直接告诉 CEO 你的目标（推荐）**

```
@ceo 我想在下个月把 MAU 提升 20%，帮我制定一个完整的增长计划
```

**② 直接找对应部门负责人**

```
@product_lead 用户留存下降了，帮我分析一下原因并给出改进方案
@tech_lead 我们的页面加载很慢，帮我诊断并给出优化方案
@growth_lead 帮我制定下个季度的内容营销计划
```

**③ 直接找执行角色获取专业输出**

```
@data_analyst 给我输出一份本周的核心数据周报
@feature_planner 帮我写一个用户反馈收集功能的 PRD
@seo_specialist 分析我们网站的 SEO 现状，给出优化建议
```

---

### 输出格式约定

每个 Agent 的输出都遵循结构化格式，方便直接使用：

| Agent 类型 | 典型输出格式 |
|-----------|-------------|
| CEO | 决策摘要 + 委派任务清单 + 成功标准 |
| 产品团队 | PRD / 用户故事 / 需求优先级列表 |
| 技术团队 | 技术方案 / 架构设计 / 工时估算 |
| 增长团队 | 增长策略 / 完整文案 / 数据分析报告 |
| data_analyst | 数据表格 + 关键发现 + 行动建议 |
| qa_engineer | 测试报告 + Bug 列表 + 发布建议 |

---

### 最佳实践

**✅ 推荐做法**

- 描述**目标和背景**，而不只是要求具体动作（让 CEO 来做任务拆解）
- 使用 `@agent_id` 精准触达，避免歧义
- 对重要决策提供**数据上下文**（当前指标值、历史趋势）
- 允许 Agent 主动向你**提问澄清**，这会让输出更准确

**❌ 避免做法**

- 不要同时向多个 Agent 发送矛盾指令
- 不要跳过 CEO 直接让执行角色做战略决策
- 不要在没有数据的情况下要求 data_analyst "分析数据"
- 不要要求 tech_lead 绕过 qa_engineer 直接上线
